# 旧链路 vs 新链路 完整对比

> 旧链路 = Wav2Vec2（英语预训练 Transformer）
> 新链路 = LTX-2 Audio VAE（语言无关的卷积压缩器）
> 
> 下面用 ★旧★ 和 ★新★ 标注每一步的区别，【相同】标注不变的部分。

---

## 二、区别总结

### 只有 3 处不同

| # | 在哪里不同 | 旧链路 (Wav2Vec) | 新链路 (LTX-2 VAE) |
|---|-----------|-----------------|-------------------|
| 1 | **离线提取** | Transformer 编码 → (T, 12, 768) | 卷积 VAE 编码 → (T, 128) |
| 2 | **Dataset unsqueeze** | 不需要 (已经是 4 维) | `unsqueeze(2)` 补 blocks 维度 |
| 3 | **AudioProjModel.proj1** | Linear(**46080**→512) | Linear(**640**→512) |

### 完全一样的部分

- temporal window ±2 帧
- 5% audio dropout
- proj2, proj3, Conv1d, LayerNorm
- 输出都是 (1, 13, 32, 768)
- 42 层 Transformer cross-attention
- loss 计算、backward、optimizer

## 三、为什么要换？

```
★旧★ Wav2Vec2 的问题:

  英语训练 → 学到的是英语音素
  │
  ├─ 说英语 → 特征质量高 → 嘴型准
  └─ 说中文/日语 → 特征质量差 → 嘴型不准
  
  比喻: 请了一个只懂英语的翻译，翻中文就乱翻


★新★ LTX-2 VAE 的优势:

  直接压缩声学信号 → 和语言无关
  │
  ├─ 说英语 → 嘴型准
  ├─ 说中文 → 嘴型也准
  └─ 说任何语言 → 都准
  
  比喻: 不翻译内容，只记录嘴巴的物理运动（频率+能量+时间）


★新★ 的代价:

  每帧信息从 9216 个数 → 128 个数 (少了72倍)
  但: 对于"嘴巴该怎么动"这个任务，128 个声学特征可能就够了
  多出来的 9000 个数大部分是语义信息（"说了什么词"），对画嘴型没用
```

## 四、9216 → 128 会丢失数据吗？

会丢信息，但丢的大部分是**对画嘴型没用的信息**。

### 旧链路 9216 个数里装了什么

Wav2Vec2 有 12 层，每层学到的东西不一样：

```
第 1-3 层（底层）：声学特征 — 频率、能量、音调变化
                  → 对画嘴型有用 ✅

第 4-8 层（中层）：音素特征 — 正在发什么音（p/b/a/i...）
                  → 对画嘴型有用 ✅

第 9-12 层（高层）：语义特征 — 正在说什么词、什么语法结构
                   → 对画嘴型没用 ❌
                   → 而且是英语语义，碰到中文直接乱掉
```

9216 个数里，真正控制嘴型的可能只有前几层的信息。高层的语义信息对"嘴巴该张多大"没什么帮助——你说 "hello" 和 "yellow"，嘴型差别很大，但 Wav2Vec 高层觉得它们语义完全不同会给出很不一样的特征，这反而是噪声。

### 新链路 128 个数里装了什么

```
纯声学信号：频率 + 能量 + 时间变化
  → 这一刻嘴巴需要张多大、舌头在哪、是否送气
  → 128 个数足够编码这些物理信息
  → 和语言无关：中文的 "a" 和英语的 "a" 嘴型一样，特征也一样
```

### 比喻

```
旧链路：录了一本 72 页的笔记（9216 个数）
        前 10 页是嘴巴怎么动（有用）
        后 62 页是他在说什么英语单词（对画嘴型没用，碰到中文还会写错）

新链路：只录了 1 页精华笔记（128 个数）
        只记嘴巴怎么动（全是有用的）
        不管他说的是什么语言
```

### 风险与验证

确实存在信息瓶颈的风险——万一 128 个数不够表达复杂的嘴型动作（比如快速连续说话），效果可能不如旧链路。所以需要消融实验来验证：

| 实验 | 对比什么 | 结论 |
|------|---------|------|
| A: 旧编码器 + 英语数据 | 基线 | — |
| B: 新编码器 + 英语数据 | 128 个数够不够？ | B ≈ A → 9000 个高层特征是冗余的 |
| C: 旧编码器 + 多语言数据 | 旧编码器跨语言行不行？ | C << A → 英语编码器跨语言确实差 |
| D: 新编码器 + 多语言数据 | 最终方案 | D >> C → 新编码器跨语言确实好 |

如果 B 比 A 差很多 → 128 确实不够，需要加大维度或调整 AudioProjModel。
如果 B 和 A 差不多 → 旧链路的 9000 多个高层特征确实是冗余的，新链路是更好的选择。
