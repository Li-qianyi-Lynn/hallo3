### Phase 3: 多卡训练验证 (9月24日完成)

在 2x RTX Pro 6000 上交互式测试, 确认多卡通信正常:

| 问题 | 原因 | 修复 |
|------|------|------|
| `FileNotFoundError: configs/` | `cd ~/hallo3/hallo3` 后相对路径错误 | config 路径改为 `../configs/` |
| `train_data` 路径找不到 | 同上, data/ 在上层目录 | 改为 `../data/talkvid_4k.json` |
| `CUDA error: invalid device ordinal` | SLURM 分配 GPU 数 < 脚本 nproc | 改用 `nvidia-smi -L | wc -l` 动态检测 |
| OOM (SIGKILL exitcode -9) | 2 进程加载模型, 128G 内存不够 | 改为 256G (正式训练 512G) |
| `IndexError: index 127 out of bounds for size 127` | 视频帧索引直接用于 audio_emb, 但 LTX-2 VAE 时间维度 != 视频帧数 | 添加线性缩放映射 `frame_idx / video_len * audio_len` |

最终结果:
- 2 卡训练成功启动, loss 正常输出: `iteration 9/5000 | loss 6.18E-02`
- 两张卡均有显存占用和 100% 利用率
- NCCL 通信正常

### Phase 4: 推理脚本适配 LTX-2 VAE (9月24日完成)

`sample_video.py` 原来推理时用 wav2vec 实时处理音频，和训练时的 LTX-2 VAE 不匹配。

修改内容:
- 新增 `sgm/utils/ltx_audio_processor.py` — `LTXAudioProcessor` 类，接口与旧 `AudioProcessor` 一致
- `sample_video.py` — 根据 `--vae_checkpoint` 参数自动选择编码器
- `arguments.py` — 新增 `--vae_checkpoint` 命令行参数

推理用法:
```bash
# 用 LTX-2 VAE (新 encoder)
python sample_video.py \
    --vae_checkpoint /scratch/li_qiany_neu/pretrained_models/ltx2.5/vae/ltx-2.5-audio-vae-bf16.safetensors \
    ...

# 用 wav2vec (旧 encoder, 不传 --vae_checkpoint 即可)
python sample_video.py --wav2vec_model_path ... ...
```

核心逻辑: LTX-2 VAE 输出的时间步 (T_vae) 与视频帧数不 1:1 对应，通过线性插值对齐到 fps-based 帧数后，复用原有的滑动窗口和分段生成逻辑。
