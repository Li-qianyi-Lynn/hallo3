# 2026-10-30：Adapter 随机初始化问题分析与改进方案

承接 [2026-10-30_g1_commands.md](2026-10-30_g1_commands.md)。

---

## 一、问题

G1 训练 500 步后推理 1 条视频，SyncNet 打分：

| 条件 | Confidence | Min dist | AV offset |
|------|-----------|----------|-----------|
| 真值 | 7.478 | 7.077 | −1 |
| 原版 Hallo3（预训练） | 7.278 | 8.286 | −2 |
| LTX-2 VAE 7000 步 | 0.736 | 13.777 | 6 |
| **G1 Omnilingual 500 步** | **1.069** | **13.593** | **5** |

G1 500 步的结果和 LTX-2 VAE 7000 步几乎一样差——口型完全没被音频驱动。

---

## 二、根因分析

### 2.1 adapter 随机初始化 = 给预训练权重喂垃圾

原版 Hallo3 的数据流是**端到端配合好的**：

```
wav2vec2-base (768维)
    → proj1 (预训练，学会了"从 768 维特征中提取口型信号")
    → proj2 → proj3
    → cross-attention → 驱动口型
```

conf = 7.278，口型正确。

G1 插入了随机初始化的 adapter：

```
Omnilingual (1024维)
    → adapter (随机初始化！输出无意义的 768 维向量)
    → proj1 (预训练权重，但收到的是垃圾输入)
    → proj2 → proj3
    → cross-attention → 口型不动
```

conf = 1.069，和噪声基线一样。

**关键**：proj1 的预训练权重期望的输入是"wav2vec2-base 的 768 维特征分布"。adapter 随机初始化输出的 768 维向量与这个分布完全不同，proj1 无法从中提取有效信息。这等于把 proj1 的预训练优势完全浪费了。

### 2.2 为什么 500 步不够

1. **梯度信号弱**：训练 loss 由整体视频质量决定（纹理、结构、运动），audio cross-attention 只影响口型区域。模型可以靠人脸图片条件生成"看起来还行"的视频（loss ~0.048），不需要用音频信息。所以流向 adapter 的梯度很弱。

2. **adapter 要学的不是简单的映射**：adapter 需要学会把 Omnilingual 特征变换到"wav2vec2-base 特征空间"，这样后面的 proj1-3 才能正常工作。从随机开始学习这个特征空间对齐，需要大量步数。

3. **对比之前的经验**：LTX-2 VAE 的 proj1 也是从随机初始化，跑了 7000 步 conf 仍然只有 1.04。虽然那次失败的主因是 encoder 类型错误，但"随机初始化的投影层需要很多步才能收敛"的问题是一样的。

### 2.3 7000 步可能也不够

存在的风险：
- 模型可能学会**绕过音频**——只用人脸图片生成视频，audio pathway 梯度持续很弱
- adapter 只有 ~79 万参数但学习率和其他 22 亿参数一样（1e-5），相对学习速度慢
- 没有显式的音频-口型对齐监督信号（loss 只看整体视频质量）

## 三、改进方案：线性回归初始化 adapter

### 3.1 核心思路

Omnilingual 和 wav2vec2-base 都是 wav2vec2 架构、自监督语音表征模型，特征空间有相关性。可以用数据拟合一个线性映射作为 adapter 的初始化：

```
用几十条音频 → 同时提取两组特征
  wav2vec2-base:  (T, 12, 768)   — proj1 期望的输入
  Omnilingual:    (T, 12, 1024)  — adapter 的输入

线性回归: W, b = argmin || Omnilingual @ W.T + b - wav2vec2-base ||²

用 W, b 初始化 adapter → adapter 从第一步就输出≈wav2vec2-base 特征
```

### 3.2 效果对比

| | 随机初始化 | 回归初始化 |
|---|---|---|
| adapter 初始输出 | 无意义的 768 维向量 | ≈ wav2vec2-base 的 768 维特征 |
| proj1 收到的输入 | 与预训练分布不匹配 → 输出垃圾 | 与预训练分布接近 → 输出有意义的 tokens |
| 训练起点 | 从零学习特征空间对齐 | 已有不错的对齐，微调即可 |
| 预期 500 步 conf | ~1（已验证） | 应接近原版水平（~6-7） |

### 3.3 实现步骤

1. 取 50 条音频（从训练集抽样）
2. 分别用 wav2vec2-base 和 Omnilingual 提取特征（取最后 12 层）
3. 对每一层分别拟合，或把所有层拉平一起拟合
4. 得到 `W (768, 1024)` 和 `b (768,)` 
5. 保存为 `adapter_init.pt`
6. 训练时加载：`model.audio_proj.adapter.weight.data = W`，`model.audio_proj.adapter.bias.data = b`

拟合本身很快（几秒），主要时间在提取两组特征（需要加载两个模型，~10 分钟）。

### 3.4 为什么线性回归就够了

adapter 本身就是一个 `Linear(1024, 768)`，和线性回归的形式完全一致。我们不是在做近似——adapter 的数学形式就是 `y = xW.T + b`，线性回归求的也是 `y = xW.T + b`。所以回归拟合得到的就是 adapter 能表达的最优初始映射。

## 四、其他备选方案

### 方案 B：冻结其他参数，只训 adapter

- 冻结 DiT、proj1-3 等所有参数，只让 adapter 的 ~79 万参数参与训练
- 优势：所有梯度集中到 adapter，学得更快
- 劣势：adapter 能力有限（只是线性映射），可能不够表达
- 适合场景：配合方案 A（回归初始化），先用回归初始化 + 冻结微调几百步，再解冻全部

### 方案 C：给 adapter 更高的学习率

- adapter 用 1e-3，其他参数用 1e-5（差 100 倍）
- 需要自定义 optimizer 的 param_groups
- 可以和方案 A 组合

### 方案 D：两阶段训练

- Stage 1：回归初始化 adapter → 冻结其他参数 → 只训 adapter 500 步（lr=1e-3）
- Stage 2：解冻 audio 相关层 → 全部训练 7000 步（lr=1e-5）
- 最稳妥但最复杂

## 五、推荐执行顺序

```
1. 写拟合脚本，生成 adapter_init.pt          — 需要 GPU，~10 分钟
2. 修改训练代码，加载 adapter_init.pt 初始化   — 代码改动
3. 重新训练 G1（从 adapter_init 开始）         — 7000 步
4. 500 步时推理一条看 conf                     — 快速验证
5. 如果 500 步 conf > 3，继续跑完 7000 步
6. 如果 500 步 conf 仍然 ~1，考虑方案 B/C/D
```
